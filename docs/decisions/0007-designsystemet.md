# 0007 Designsystemet as the component system

Date: 2026-10-09 · Status: accepted

## Context
The interface was built from our own small component set and read as plain and
generic. Eric asked for a redesign on Digdir's Designsystemet, with as few custom
overrides as possible and more of the primary colour. `docs/design/brand.md` says
where that colour goes and what must stay ours.

## Decision
- Components come from `@digdir/designsystemet-react` 1.23 and their CSS from
  `@digdir/designsystemet-css`, imported per component (Bun's CSS parser cannot read
  the package's `index.css`). `app/src/ui/` wraps them only where Scientia adds
  behaviour: field errors that keep focus on the first invalid field, dialogs that
  focus their first field and restore focus on close, rows, toasts, page header.
- The theme is generated by the Designsystemet CLI from `designsystemet.config.json`
  (`accent` `#1f4f8a`, warm `neutral` `#5e5646`, radius 6, Inter) into
  `app/src/theme/` with `mise run theme`. It is never edited by hand. The system
  lightens the neutral scale, so the page background lands on `#f4f3f2` whatever the
  input.
- The root carries `data-color-scheme="auto" data-color="accent"`. Size `md` is the
  theme's default, so the root has no `data-size`: on `<html>` it sets the root font
  size to 18 px and every `rem` in the system grows by an eighth. Lists and tables use
  `data-size="sm"`.
- Neutral panels with blue content: a list, table, form panel or empty state is a
  Card or Table in `data-color="neutral"`, and its rows or body go back to
  `data-color="accent"`. Borders and surfaces stay neutral; links and buttons inside
  stay blue. Course cards and "need grading" panels are `accent` and `tinted`.
- Cascade layers `reset, ds, app` (declared in `app/src/layers.css`, which must be
  imported first because the bundler hoists imports). Our layout rules sit in
  `app` and win without specificity games or `!important`.
- Ours, because the system has none: top bar, course navigation, page header,
  list row layout, sub-navigation between pages (links styled as tabs, since
  Designsystemet's Tabs switch panels in place and these are pages with URLs),
  calendar grid, sticky table columns, toast, unread count (the system's Badge
  prints its number from CSS, which is not page text).
- The account menu is the system's Dropdown opened by our own top-bar button through
  `popovertarget`, so the trigger can use the bar's contrast colours.
- File fields use the system's (experimental) FileUpload area around a native input.
- Dialogs have no close icon: every dialog has a Cancel button, and the icon would
  take the first focus.
- Development serves without hot module reload: Bun's HMR breaks on a circular import
  inside designsystemet-react. `bun --hot` still restarts on change.

## Consequences
- The JavaScript bundle grows by about 70 KB gzipped (the React package is not
  tree-shakable and pulls in designsystemet-web). The budget is 250 KB.
- Headings use the system's medium weight; the theme CLI has no setting for it.
- In dark mode the solid top bar is the accent's dark-scheme base, a light blue,
  as the system does for primary buttons.
- Upgrading Designsystemet means re-running `mise run theme` and the e2e suite.
