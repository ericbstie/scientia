## What worked
- **Parallel worktree slices on separate slots.** Four slices merged with no
  e2e interference, and coverage went from 4.7 to 100 in one milestone.
- **Review, then fix, then regression spec.** The security review found 8
  blockers, all fixed in 0007 and `app/server.ts`. `e2e/security.spec.ts`
  (US-43) now keeps them fixed.
- **Blind think-aloud tests** (added mid-milestone by the product owner) found 16
  problems that 116 green e2e tests missed. The worst was in admin: a label clash
  made the new role land in the list filter, and a wrong role could not be
  corrected (`docs/process/reviews/m3-user-test.md`).
- **Sonnet gap research.** `docs/research/gap-analysis.md` ranks 37 gaps with
  sources. Top ten: quizzes, weighted categories, rubrics, per-student due dates,
  course copy, marks without a submission, bulk import and course management,
  email digest and password reset, co-teachers, groups.

## What hurt
- **e2e proves the stories we wrote, not that a newcomer can follow the UI.**
  Every e2e test passed while the admin flow failed for a fresh user. Root cause:
  no definition of done or metric looked at first-use success. Copy and flows
  were only checked against the stories. Partly fixed mid-milestone (`copy.leaks`,
  user-test skill, `scripts/look.ts`, WORKFLOW rule, user-tester role). The
  missing piece was a tracked number, added below.
- **Workarounds instead of blockers.** The content and work agents emulated
  missing schema in the client. Root cause: the slice briefs said "describe the
  SQL and work around it if you can", and the implementer rule did not ban it.
  Each case cost a migration and a rework commit.
- **A broken shared fixture reached four parallel agents.** `signIn` went to
  `/signin` but the route is `/sign-in`. Agents wrote local sign-in helpers until
  fc5c6ae. Root cause: the only spec run before dispatch (`e2e.total` 1) never
  called `signIn`, and Preflight checked tools, not the shared test harness.
- **Metrics that lie quietly.** A `--reporter=line` run left an old
  `report.json`, and `process.retro_changes` failed silently. Root cause: the
  script had no staleness check and swallowed shell errors. Both fixed in
  `scripts/metrics.ts`.
- **Model choice changed mid-milestone.** The product owner ruled that every
  change-making agent runs on opus at high effort. `roles.md` and
  `.claude/agents/*` already say so. The brief template still offered a free
  model choice, and is aligned below.
- The M2 retro folded into a product commit (f219af2) was already fixed by the
  M2 skill change. 6206275 shows that fix worked.
