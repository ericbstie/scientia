Research: 7 notes, 150+ cited sources. Every research brief was met on the
first report (7/7), each in about 3 minutes on haiku running in parallel.

## What worked
- **Parallel haiku research with one shared structure.** Identical section lists
  made the synthesis straightforward; the analyst merged seven files in one pass.
- **Two reviewers with different lenses.** Testability found 5 blockers and 25
  should-fix items; research-fit found 8 should-fix items. Neither lens alone
  would have caught both kinds.
- **Reviews caught a security gap**, not just wording: the analyst, checking
  stories against the schema, noticed every user could read every email. Fixed
  with ADR 0006 before any feature code depended on it.

## What hurt
- **Stories were written before the demo data existed as code.** The first draft
  asserted texts, times and files the seed did not have (5 blockers). Root cause:
  the brief described demo data in prose and nobody owned it. A whole revision
  round (≈5 min sonnet) went into aligning stories with `supabase/seed.ts`.
- **Wall-clock dependence** was the largest class of testability findings
  ("today", calendar months). Root cause: no rule for time in story criteria.
- **IA and primitives drifted.** The IA plan had to list fixes to existing UI
  primitives (status words, date format) because the primitives were written
  before the guidelines. Cheap to fix now, but it would have been expensive later.

## Changes applied
| File | Change | Expected effect (metric) |
| --- | --- | --- |
| `docs/process/WORKFLOW.md` | Contract artifacts rule: demo data, schema and status vocabulary are single-owner code files that stories and designs cite; story sets get a two-lens review before implementation | Fewer review blockers per story set |
| `.claude/agents/analyst.md` | Criteria must quote exact UI strings, use time relative to the seed, and cite only data in `supabase/seed.ts` | Testability blockers → 0 in later story work |
| `docs/process/roles.md` | Reviewer lenses list now includes "security" for schema/RLS changes | Security gaps caught at review, not in e2e |
| `.claude/skills/retro/SKILL.md` | Commit retro files on their own with explicit paths (this retro was accidentally folded into the product commit `f219af2`) | `process.retro_changes` measurable every milestone |
| `.claude/agents/implementer.md` | Must use `scripts/slot.sh` and never share a stack | No cross-agent e2e interference in M3 |
