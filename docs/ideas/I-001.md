# I-001 Keep a typed answer until it is submitted

Stage: `gate2-kept`. Pain point: lost work (synthesis, pain point 10). US-9 keeps the text only when a submit fails on the same page; a closed tab, a crash, an expired session or a lost connection still loses it.

## How the flow changes

Before: Maya opens an assignment that takes text, types for twenty minutes, her laptop sleeps and the tab reloads. The box is empty.

After: the same page, the same box. What she types is kept on her device. When she comes back to the assignment the box already holds it, and one muted line sits under the field: **Restored your unsent answer.** The line goes away at her first keystroke. Submit works as before and then forgets the draft.

Nothing else changes: no "Save draft" button, no new status, no toast, no new page, same click count. A student never has to know the feature exists until it saves them.

## Design

- **Where:** the existing "Your answer" `TextArea` on the assignment page (`SubmitForm`). Uses the field's `hint` slot, so it looks like every other hint (muted, under the field, linked with `aria-describedby`).
- **What is kept:** the typed answer only. A chosen file cannot be kept; the page does not promise it.
- **When it is saved:** half a second after typing stops. An empty box removes the draft.
- **When it is restored:** on opening the assignment, if a draft exists and differs from the answer already submitted (if any). The restored text replaces the submitted text in the box; the submitted text is still shown above as today.
- **When it is forgotten:** on a successful submit; on sign-out (the next person on a shared computer finds nothing); after 30 days, silently on the next visit.
- **Who it belongs to:** one draft per person per assignment. Someone else signing in on the same browser sees an empty box.
- **Where it lives:** the browser's local storage, not the server. No schema, no RLS surface, no "draft" state for students. Consequence, stated honestly in the brief: a draft does not follow the student to another device.
- **If storage is blocked or full:** silent. The form behaves exactly as it does today; no error, because there is nothing the person can do about it.
- **Hidden when:** the assignment is closed or graded (the form is not shown, so nothing is restored).

## Brand check

Exact: says what happened and that it is not sent. Fair: a student's work is never lost to the interface. Calm: invisible until it matters, one line, no motion. Rules 1 to 8 hold: no new colour, shape, word class or place.

## Tests and metrics

- Extend US-9: type an answer, reload, the text is back with the line; edit, the line goes; submit, reload, the box shows the submitted text and no line; a second student on the same browser sees an empty box.
- No change to clicks, bundle (a few hundred bytes) or a11y scan.

## Questions for the architect

- Is local storage acceptable for student text on shared machines, given sign-out and 30-day clearing? The alternative (a server draft table with RLS) is rejected for adding a state students do not have today.
- `useDraft(key)` as a hook in `lib/` so Discussions replies could use it later; not part of this idea.
