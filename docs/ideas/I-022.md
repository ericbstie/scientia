# I-022 Admin navigation without dead ends

Stage: `gate2-kept`. An admin has no courses of their own, so Calendar is an empty month and Notifications is always "No notifications". Both are in their top bar anyway, next to a link called "Admin" that holds the two places they actually use.

## How the flow changes

Before (admin): top bar `Scientia  Calendar  Admin  Notifications  Name ▾`. After signing in they land on Users; Users and Courses are tabs under the page title.

After: top bar `Scientia  Users  Courses  Name ▾`. Users and Courses are the main navigation, highlighted when current like Dashboard and Calendar are for everyone else. The tabs under the title are gone, because two navigations for the same two places is one too many. There is no Calendar, no bell, no Dashboard.

Signing in still lands on Users. `/calendar` and `/notifications` still open if typed; this removes links, not access.

## Design

- **Top bar:** `NavLink`s "Users" and "Courses" (`/admin/users`, `/admin/courses`) in the same `.nav-link` style, with the current one marked by `aria-current`. Nothing else in `.topnav`.
- **Pages:** delete `AdminNav` and its two uses. The page header (title, New user or New course action) sits directly under the top bar, the same as every other list page.
- **Phone:** the top bar already wraps the navigation under the brand and account menu; two short links fit on one row.
- **Account menu:** unchanged (Settings, Sign out).
- **Course pages for admins:** unchanged; an admin reaches a course through People in the Courses table.

## Brand check

Same place for the same thing: main navigation is the top bar for everyone. Calm: fewer items, none that lead nowhere. Exact: the link says what is there.

## Tests and metrics

- Admin specs that click the Users or Courses tab click the top-bar link of the same name; one new assertion that an admin's top bar has no Calendar or Notifications link.
- Click budget: an admin reaches Users or Courses in one click, as before.
